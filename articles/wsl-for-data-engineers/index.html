Why Data Engineers Use WSL and How to Set It Up in 5 Minutes

Data engineering often requires tools that are built for Linux first, such as Docker, Python, PostgreSQL clients, or distributed processing frameworks. Setting these up directly on Windows can be frustrating. A full switch to Linux is not always practical - many organisations rely on Windows for Active Directory, Power BI, or Office integration - and virtual machines can be heavy and slow. WSL offers the best of both worlds: a native Linux shell inside Windows, with minimal overhead. You keep Windows-only apps and workflows, while still accessing Linux tooling and even browsing your Windows folders directly from WSL. In this guide, I’ll walk you through the steps I used to set up WSL, configure it for development, and highlight why each step matters for data engineering projects.

Step 1: Verify Windows build

Press Win + R, type winver, press Enter. 

winver

Note the version and OS build numbers.

For reference:

  • Build 19041 or later → you can use the modern wsl --install command.
  • Older than 19041 → you must do the manual feature enablement.

Step 2: Check WSL status

Open PowerShell as Administrator.

Then run: 

wsl --status

If you see something like this, it is nice - your Windows environment is new enough to support WSL2 directly. That makes life much easier.

If it errors with “Unrecognized option” or something similar, that means your build doesn’t support the new unified command - we’ll need to go manual.

Step 3: Install WSL and Ubuntu

In the same Admin PowerShell terminal, run: 

wsl --install -d Ubuntu

This does three things in one go:

  • Installs the WSL engine.
  • Sets the default version to WSL2.
  • Downloads Ubuntu from the Microsoft Store.

After the install finishes, you’ll likely need to restart Windows.

Step 4: First launch and create your Linux user

After reboot:

  1. In Start Menu, search for Ubuntu and open it.

  2. It will run some setup, then ask for a new UNIX username and password.

    🔒 You’ll be asked for your password here - just type it (nothing will show) and press Enter.

    • “Installing, this may take a few minutes…” stage.
    • This user is your WSL Linux account - it doesn’t have to match your Windows username.

Once you’re in and see the Ubuntu prompt like: 

yourname@DESKTOP-XXXX:~$

…you’re inside Linux! 🎉 Nice - you’ve got your Linux shell alive and humming inside Windows. That’s a big milestone. 🚀

Step 5: Update and upgrade packages in WSL

In your Ubuntu shell (inside WSL), run these commands:

  • fetch the latest package lists 
sudo apt update
  • upgrade all installed packages 
sudo apt upgrade -y
  • optional: remove outdated cached packages 
sudo apt autoremove -y

You’ll need to enter your password during installation.

And That’s It 🚀 (TL;DR)

Quick recap if you just want the steps fast:

  1. Verify Windows build → check with winver
  2. Check WSL status → run wsl --status in Admin PowerShell
  3. Install WSL & Ubuntu → wsl --install -d Ubuntu
  4. Launch Ubuntu & create user → set up your Linux account
  5. Update packages → sudo apt update && sudo apt upgrade -y

Now you’re ready to run Python, Docker, and PostgreSQL like a Data Engineer - all inside Windows. 🎉

With WSL up and running, you’ve laid the foundation for data engineering work: Python, Docker, PostgreSQL, and other Linux-first tools will feel right at home here. The best part is that you can use them alongside Windows-only apps like Power BI without friction.
